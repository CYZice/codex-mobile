# ChatGPT conversation reference

The composer can reference an existing ChatGPT conversation without creating a new project or exposing the full remote transcript to the web UI. Opening `+`, or typing `@` at the start of a draft or after whitespace, lazily requests normalized summaries from the local bridge. Selecting a result replaces the active `@query` with a non-editable inline reference node inside the same ProseMirror paragraph. The reference serializes as `[title](chatgpt-conversation://conversation-id)`, matching Codex Desktop rather than using a separate chip row above the editor.

The bridge owns ChatGPT authentication and upstream API calls. It deliberately returns only `conversationId`, `title`, `updatedAt`, and a bounded preview. The preview walks the selected branch's `current_node` ancestry, includes user and completed assistant messages, starts at the third-latest user turn, and limits each text item to 2,000 characters. This keeps credentials and the full conversation payload server-side while preserving the Desktop workflow. If authentication or the upstream request is unavailable, the menu remains usable and selection falls back to a title-only reference.

At submission time the visible Markdown link remains in the prompt and a separate `## Referenced ChatGPT conversation:` block is appended. That block marks the data untrusted and carries `conversationId`, `title`, and `priorConversation`. When the preview is null or insufficient, its instruction tells the agent to call `read_thread` with the conversation id and a turn limit of 10, following the cursor for older turns when needed. This is how Desktop makes the reference readable without pasting the full transcript into the editor.

The `+` menu groups content as Add, Plugins, and ChatGPT conversations. The same results are searchable through repeated inline `@query` triggers. The `$` skill picker remains skill-only and uses the same composer surface contract. Desktop permissions are rendered beside `+` using the short preset label; mobile retains its original top-of-input permission/model arrangement.
